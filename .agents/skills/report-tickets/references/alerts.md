# Requested alerts and publication

Corely has no inherited workload thresholds, account exemptions, Slack routing or review-age policy
from TruckerPoints. Ordinary reporting returns in chat. Configure/evaluate alerts only when the
user supplies or authorizes the relevant policy; separate account totals from verified person totals.

For an authorized review-wait alert, establish the current unanswered review cycle, responsible
reviewer, author, exact PR head and elapsed time. PR creation/update time is not enough. Missing
identity/history coverage means unknown, not no alerts. Do not copy account exemptions by familiarity.

For explicitly requested publication, verify destination and identity, prepare the content, respect
the current tool's limits and send sequentially. Keep one topic/thread and complete ticket rows.
Mention people only when requested and identities are verified; no blanket channel pings. Retain
confirmed receipts/permalinks and read back coverage. After an ambiguous result inspect the
destination before retrying, so a partial report is not duplicated. Updating another author's post,
creating channels or scheduling recurring work requires its own request.
